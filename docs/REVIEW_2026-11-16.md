# awsome-games 深度审查与修复报告（2026-11-16）

## 范围与证据

审查对象为上一轮交付的 `awsome-games-source.zip`（本地工作树）与 GitHub `1998x-stack/awsome-games` 的实际默认分支。**初检时远程仓库只有 README；现已通过 GitHub 写入接口把完整核心源码、测试、工作流和 SQLite 提交到了 `main`。** 初始化脚本因 GitHub App 缺少 workflow 写权限而推送失败，随后使用 Git 对象接口分批提交普通文件，已在实际 GitHub Actions 通过目录和数据库验证。

基线：155 个作品、54 个仓库、150 条作品-仓库映射、59 个有 demo 的作品、0 个已验证的游戏运行状态。基线仅有 7 个单元测试，不涉及真实网络克隆。

## 尚未解决或需要本地/云端运行的部分

1. 当前环境不能连接到 GitHub 的 Git 网络接口，不支持真实批量 clone / 构建 / 页面人工试玩；这不是用户本地失败的证据。
2. 目前的静态资源检查只是 HTML 中的显式引用，不分析 JS 动态 `fetch()`、CSS `url()`、WebAssembly 的加载路径或依赖后端服务。
3. 由于安全沙箱采用不透明 origin，一部分依赖本地存储、同源 `fetch()`、Service Worker 或复杂 WebGPU 权限的游戏可能受限。生产规模化时建议使用**独立域名的游戏沙箱站点**，而不是在相同 Pages origin 上放开 `allow-same-origin`。
4. 收录清单不是已验证的权利清单，第三方仓库授权必须逐项核对；大规模向公众发布的素材还需要检查图片、字体、音乐许可。
5. 生产规模下必须评估 GitHub Pages 1 GB 站点容量、带宽与 Git 对象膨胀，不能保证将任意 54 个完整仓库全部放进 Pages。
6. `entrypoint_found` 是**静态检查通过**，不是 `smoke_test_passed`，后者必须有浏览器截图、网络请求和错误日志验证支持。

## 验证步骤

```bash
python3 -m pip install -r requirements.txt

python3 scripts/build_catalog.py --check
python3 scripts/check_catalog.py

node --check site/assets/app.js
python3 scripts/collect_repositories.py --dry-run
python3 scripts/collect_repositories.py --limit 2
python3 scripts/build_site.py --preview-unapproved  # 只用于本地受限测试
```

默认 Pages 产物只包含经过授权的游戏快照；使用 `--preview-unapproved` 的生成结果不得公开部署。

## 实际开发优先级

- **P0**：把所有源文件提交到 GitHub；启用 Actions/Pages 后检查 CI green；在真实浏览器中使用单文件 HTML 的最小样例验证 sandbox。

- **P2**：增量发现 GitHub 仓库，更新源数据证据快照、哈希去重、游戏封面及多语言分类。

## 2026-11-16 远程实测补充

- GitHub `Validate catalog` 工作流实测通过，16 项测试验证通过。
- 首次 Pages 构建报告项目数 **310（错误）**，来自缺失默认种子时将 ID 不同的 fallback 记录叠加到已有 SQLite。现已修改默认种子回退行为：仅当 SQLite 为空时允许 fallback；显式指定不存在的种子应抛错。
- 为保持可重建性，新增 `scripts/export_seed.py`，可从 SQLite 恢复 stable ID 的 JSONL 文件。恢复文件包含 `_reconstruction_origin` 标记，不冒充原始采集快照。
- `Build and deploy GitHub Pages` 的构建步骤在远程执行成功，失败发生在 `actions/configure-pages@v5`：`Get Pages site failed ... Not Found`。需要管理员在 **Settings → Pages → Build and deployment → Source → GitHub Actions** 首次启用 Pages；这不是代码构建失败。
- GitHub `main` 已有 SQLite 和源码，但并未在本服务端批量克隆 54 个外部仓库、验证 155 个游戏，也未把第三方游戏源码公开部署。发布仍由 `config/publication_approvals.json` 明确许可控制。
